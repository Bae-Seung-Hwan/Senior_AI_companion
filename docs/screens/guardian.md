# 보호자 화면 구성안 (#51)

자녀(보호자)가 어르신의 **하루 요약**과 **긴급 알림**을 보고, **바로 전화**할 수 있게 하는 화면입니다.
첫 시연 목표 "말로 할 일 등록 → 보호자가 요약 받기"의 마지막 단계입니다.

> 기술 스택(#1)과 상관없이 정할 수 있는 **화면 단위의 구성**입니다. 색·글꼴·컴포넌트는 앱 프레임워크가 정해진 뒤 정합니다.
> 그림은 내용과 순서를 보여 주는 틀이고, 실제 배치는 시안에서 바꿀 수 있습니다.

## 지키는 원칙

| 원칙 | 화면에서 |
| --- | --- |
| **감시 느낌 피하기** (기획서) | 공유되지 않은 항목은 **아무 흔적도 남기지 않습니다.** "어르신이 공유하지 않은 항목", 빈 칸, 잠금 아이콘을 보여 주지 않습니다 (#51). 공유 범위가 무엇으로 되어 있는지도 보호자 화면에 보이지 않습니다 |
| 공유 범위는 어르신만 바꿈 (#41, 명세 7) | 보호자 화면에는 공유 범위를 바꾸거나 "더 공유해 달라"고 요청하는 버튼이 없습니다 |
| 잠금 화면에 민감한 내용 금지 (명세 3·4) | 푸시 본문에는 요약 `brief`, 긴급 알림 `reason`까지만. `sections`·근거 발화는 앱을 열어야 보입니다 |
| 의료 표현 금지 | 화면 문구에 "진단", "증상", 병명을 쓰지 않습니다. 요약·알림 문장은 A가 만든 그대로 보여 줍니다 (A가 이미 걸러서 보냄) |
| 전화가 가장 빠른 행동 | 어느 화면에서든 **어르신께 전화** 버튼이 한 번에 닿는 곳에 있습니다 |

보호자는 30~50대라 어르신 화면만큼 크게 만들 필요는 없지만, 긴급 알림 화면은 급할 때 보는 화면이라 글씨와 버튼을 크게 둡니다.

같은 앱에서 로그인한 사람의 역할(`role: "guardian"`)에 따라 이 화면들이 나옵니다. 보호자 가입·초대 수락은 #40, 구독 화면은 #59에서 다룹니다.

## G1. 홈

연결된 어르신마다 카드 하나. 보호자 한 명이 부모님 두 분과 연결될 수 있습니다.

```
┌─────────────────────────────────────┐
│ ⚠ 긴급 알림  사기 의심 연락           │  ← 진행 중 알림이 있을 때만 (아래 규칙)
│   14:05 · 아직 대답하지 않으셨어요  > │
├─────────────────────────────────────┤
│ 김영자 님                            │
│                                     │
│ 11월 22일 (어제)                     │
│ "오늘 AI와 여섯 번 이야기를           │
│  나누셨어요."                        │
│                        요약 보기 >   │
│                                     │
│ ┌───────────────────────────────┐   │
│ │       📞 어르신께 전화          │   │
│ └───────────────────────────────┘   │
├─────────────────────────────────────┤
│ 지난 요약 >          긴급 알림 기록 > │
└─────────────────────────────────────┘
```

- **카드에 보이는 것**: 어르신 호칭(명세 7 `display_name`), 가장 최근 요약의 날짜와 `brief`, 전화 버튼
- **진행 중 알림 배너**: 지난 24시간 안의 긴급 알림 중, 보호자가 아직 상세를 열어 보지 않았거나 어르신이 아직 대답하지 않은(`pending`) 것. 여러 개면 가장 최근 것 하나와 "외 N건"
- **보이지 않는 것**: 마지막 접속·대화 시각, 위치, 기분 아이콘(기분 공유를 켰어도 홈에는 안 둠). 홈에서 어르신의 상태를 한눈에 "모니터링"하는 모습이 되지 않게 합니다
- **첫 요약 전**: "첫 요약은 오늘 오후 9시에 도착해요" (받는 시각은 G6 설정 값)

## G2. 하루 요약 목록

```
┌─────────────────────────────────────┐
│ < 김영자 님 하루 요약                 │
├─────────────────────────────────────┤
│ ● 11월 22일 (토)                     │  ← ● 아직 안 열어 본 요약
│   오늘 AI와 여섯 번 이야기를 나누셨어요.│
├─────────────────────────────────────┤
│   11월 21일 (금)                     │
│   오늘 AI와 세 번 이야기를 나누셨어요.  │
├─────────────────────────────────────┤
│   11월 19일 (수)                     │  ← 요약이 없는 날은 줄을 만들지 않음
│   …                                 │
└─────────────────────────────────────┘
```

- 날짜 + `brief`만. 기분·일정 미리보기는 넣지 않습니다 (목록이 "기분 그래프"처럼 보이지 않게)
- **요약이 없는 날**(대화가 없어서 A가 보내지 않은 날)은 줄을 만들지 않습니다. 빈 줄이나 "대화 없음"을 보여 주면 감시처럼 느껴질 수 있습니다. 대화 없는 날을 알려 줄지는 아래 "정할 것"
- **무료 등급(주 1회)**: 맨 위에 "요약은 매주 일요일 오후 9시에 한 주 치가 함께 도착해요" 한 줄. 유료 안내는 이 한 줄 아래에 작게 한 번만 (#52 "주간 요약에 유료 전환 안내"). 긴급 알림 화면에는 유료 안내를 절대 넣지 않습니다

## G3. 하루 요약 상세

```
┌─────────────────────────────────────┐
│ < 11월 22일 (토)                     │
├─────────────────────────────────────┤
│ 오늘 AI와 여섯 번 이야기를            │  ← brief (항상)
│ 나누셨어요.                          │
│                                     │
│ 일정                                 │  ← 일정 공유를 켰을 때만
│ 오후에 치과에 다녀오셨고, 혈압약도     │
│ 잘 챙겨 드셨어요.                     │
│ 끝낸 할 일 2개                        │
│                                     │
│ 기분                                 │  ← 기분 공유를 켰을 때만
│ 손주 시험 이야기를 하시며              │
│ 즐거워하셨어요.                       │
│ 하루 기분: 좋으셨어요                  │
│                                     │
│ ┌───────────────────────────────┐   │
│ │       📞 어르신께 전화          │   │
│ └───────────────────────────────┘   │
└─────────────────────────────────────┘
```

| 칸 | 언제 보이나 | 데이터 (명세 3) |
| --- | --- | --- |
| 한 줄 요약 | 항상 | `brief` (A가 대화 횟수로 만드는 문장, #73 병합 후) |
| 일정 | 일정 공유를 켰고 내용이 있을 때 | `sections.schedule`, `stats.completed_todos` ("끝낸 할 일 N개", 0이면 줄을 안 보임) |
| 건강 | 건강 공유를 켰고 내용이 있을 때 | `sections.health` |
| 기분 | 기분 공유를 켰고 내용이 있을 때 | `sections.mood`, `mood_level` |

- **공유 범위**: 보낸 때 범위 ∩ 지금 범위 (#66에서 정함). 어르신이 철회하면 지난 요약에서도 바로 사라집니다
- **칸 순서**는 일정 → 건강 → 기분으로 고정. 칸이 없으면 제목도 없이 그냥 건너뜁니다 (자리를 비워 두지 않음)
- **`mood_level` 문구**: `good` "좋으셨어요" / `normal` "평소 같으셨어요" / `low` "조금 가라앉으셨어요". 색이나 얼굴 아이콘으로 경고처럼 보이게 하지 않습니다
- `stats.conversation_count`는 `brief`에 이미 들어 있어서 따로 숫자로 보여 주지 않습니다
- 이 화면을 열면 그 요약의 발송 기록(`notification_deliveries.opened_at`)을 남깁니다 → 기획서의 "보호자 요약 열람률" 지표

## G4. 긴급 알림 목록

```
┌─────────────────────────────────────┐
│ < 김영자 님 긴급 알림 기록             │
├─────────────────────────────────────┤
│ ● 11월 27일 14:05  사기 의심          │
│   가족·지인을 사칭해 돈을 요구하는      │
│   연락 의심 (어르신이 따르려고 하심)    │
│   아직 대답하지 않으셨어요              │
├─────────────────────────────────────┤
│   11월 20일 09:12  응급               │
│   넘어지셨다고 하심                    │
│   (지금은 견딜 만하다고 하심)           │
│   보호자 전화를 원하셨어요              │
└─────────────────────────────────────┘
```

- 한 줄에 시각, 유형("사기 의심" / "응급"), `reason`, 어르신 반응(G5 표)
- `high`는 앞에 표시를 하나 둡니다. 색은 시안에서 (빨강 한 가지만, 남발하지 않음)
- 근거 발화는 목록에 넣지 않습니다

## G5. 긴급 알림 상세

긴급 푸시를 누르면 바로 열리는 화면. **급할 때 보는 화면이라 가장 크게, 가장 단순하게** 만듭니다.

```
┌─────────────────────────────────────┐
│ 응급 · 11월 27일 14:05                │
│                                     │
│ 넘어지셨다고 하심                      │  ← reason (크게)
│ (지금은 견딜 만하다고 하심)             │
│                                     │
│ 어르신 반응                           │
│ 아직 대답하지 않으셨어요                │  ← user_response (G5 표)
│                                     │
│ 어르신이 하신 말                       │  ← 근거 발화 (아래 규칙)
│ "아까 화장실에서 넘어졌는데 견딜 만해"   │
│                                     │
│ 지금 어르신께 전화해 상태를             │  ← 안내 (유형별)
│ 여쭤봐 주세요.                        │
│                                     │
│ ┌───────────────────────────────┐   │
│ │       📞 어르신께 전화          │   │  ← 가장 큰 버튼
│ └───────────────────────────────┘   │
│ ┌───────────────────────────────┐   │
│ │       🚑 119에 전화             │   │  ← 응급일 때
│ └───────────────────────────────┘   │
└─────────────────────────────────────┘
```

### 보여 주는 것 (명세 4, DB `alerts`)

| 칸 | 내용 |
| --- | --- |
| 유형·시각 | "사기 의심" / "응급", `detected_at` |
| 무슨 일 | `reason` (A가 코드로 만든 틀, #74·#75). 그대로 보여 줌 |
| 어르신 반응 | 아래 표. 반응이 바뀌면 화면을 다시 그림 |
| 어르신이 하신 말 | `evidence_text`. **긴급 알림 동의(`emergency_alert`)를 켰을 때만** (DB README 5). 끄면 칸 자체가 없음 |
| 안내 | 유형별 한두 문장 (아래 표) |
| 버튼 | 어르신께 전화(항상, 가장 큼) + 유형별 버튼 |

### 어르신 반응 문구 (`user_response`)

| 값 | 문구 |
| --- | --- |
| `pending` | 아직 대답하지 않으셨어요 |
| `guardian_check_requested` | 가족에게 확인해 보겠다고 하셨어요 |
| `guardian_call_requested` | 보호자 전화를 원하셨어요 |
| `call_119_requested` | 119 연결을 고르셨어요 |
| `dismissed` | 괜찮다고 하셨어요 |
| `no_response` | 대답이 없으셨어요 |
| (`helpline_requested`, #68 안건) | 109 상담 전화 연결을 고르셨어요 |

### 유형별 안내와 버튼

| 유형 | 안내 | 버튼 |
| --- | --- | --- |
| 사기 (`fraud`) | "돈을 보내거나 번호를 알려 드리기 전에 어르신께 전화해 사실인지 함께 확인해 주세요." 이미 따르셨다는 `reason`이면 "이미 돈을 보내셨다면 은행과 112에 바로 알려 주세요." | 어르신께 전화, 112에 전화 |
| 응급 (`emergency`) | "지금 어르신께 전화해 상태를 여쭤봐 주세요. 연락이 닿지 않으면 119에 신고해 주세요." | 어르신께 전화, 119에 전화 |
| 응급 · 마음이 힘듦 (`self_harm`) | "어르신께 먼저 전화해 이야기를 들어 주세요. 109에서도 상담할 수 있어요." | 어르신께 전화, 109에 전화 |

- **`self_harm`은 근거 발화를 기본으로 숨깁니다** (동의를 켰어도 "어르신이 하신 말 보기"를 한 번 더 눌러야 보임). #68 11/28 B 추천
- 이 화면을 열면 그 알림의 발송 기록에 `opened_at`을 남기고, **아직 안 보낸 5분 뒤 재알림(`re_alert`)을 취소**합니다 (#65 DB, #37 명세 4)
- 전화 버튼은 앱이 전화를 직접 거는 게 아니라 휴대폰 전화 앱을 번호와 함께 엽니다. 어르신 번호는 이 화면을 그릴 때만 B 서버에서 받습니다 (명세 7에는 번호가 없음, 보호자 앱 전용)

## G6. 보호자 설정

```
┌─────────────────────────────────────┐
│ < 설정                               │
├─────────────────────────────────────┤
│ ⚠ 긴급 알림이 소리 없이 와요           │  ← 알림 권한·긴급 채널이 꺼져 있을 때만
│   설정에서 켜 주세요             >    │
├─────────────────────────────────────┤
│ 요약 받는 시각          오후 9시  >   │
│ 방해 금지 시간    오후 10시~오전 7시 > │
│   (긴급 알림은 이 시간에도 와요)        │
├─────────────────────────────────────┤
│ 연결된 어르신                         │
│   김영자 님                      >   │  ← 연결 끊기
├─────────────────────────────────────┤
│ 구독                             >   │  ← #59
└─────────────────────────────────────┘
```

- **알림 권한 경고가 가장 중요합니다.** 긴급 알림은 푸시가 전부라서(MVP는 알림톡 없음), 알림이 꺼져 있거나 Android 긴급 채널·iOS 시간 민감 알림이 꺼져 있으면 맨 위에 경고를 둡니다. 홈에도 같은 경고를 한 줄 띄웁니다
- **방해 금지 시간**: 명세 7 보호자 `preferences.quiet_hours`. "긴급 알림(`high`)은 이 시간에도 온다"는 것을 같이 적습니다
- **요약 받는 시각**: 아래 "정할 것" 2번
- **보호자가 바꿀 수 없는 것**: 공유 범위, 어르신 호칭·복약 시간 등 (#43 원격 설정은 별도 화면, 어르신 동의 후 적용)

## 푸시 문구

| 종류 (`kind`) | 제목 | 본문 |
| --- | --- | --- |
| 하루 요약 (`report`) | 김영자 님 하루 요약 | `brief` |
| 주간 요약 (무료) | 김영자 님 이번 주 요약 | "이번 주 요약 N개가 도착했어요" |
| 긴급 알림 (`alert`, `re_alert`) | 사기 의심 / 응급 | `reason` |
| 긴급 알림 · 마음이 힘듦 | 김영자 님께 연락해 주세요 | "앱에서 내용을 확인해 주세요" (아래) |
| 후속 (`follow_up`) | 김영자 님 | "괜찮다고 하셨어요" 등 반응 문구 |

- 제목에 "어르신이 위급" 같은 고정 문구를 쓰지 않습니다. 함께 있는 분이 위급한 경우(`other_person`)도 있어서 `reason`을 따릅니다 (#75 리뷰)
- **`self_harm`은 잠금 화면에 `reason`도 넣지 않습니다.** "죽고 싶다는 등 마음이 많이 힘들다고 하심"이 잠금 화면에 뜨면 주변 사람이 볼 수 있어서입니다. 앱을 열면 G5에서 보입니다

## B 서버에 필요한 것 (보호자 앱 ↔ B, A와는 무관)

명세(A ↔ B)가 아니라 B 안의 API라서 `docs/api-contracts.md`에는 넣지 않습니다. 기술 스택이 정해지면 같이 만듭니다.

| API (가칭) | 화면 | 데이터 |
| --- | --- | --- |
| `GET /guardian/seniors` | G1 | 연결된 어르신, 최근 요약 `brief`, 진행 중 알림 |
| `GET /guardian/seniors/{id}/reports` | G2 | 요약 목록 (공유 범위로 거른 모양, mock `guardian_view`와 같은 규칙) |

## 정할 것 (#68)

1. **대화 없는 날**: A는 요약을 보내지 않음 (#73). B 추천: 기본은 아무것도 안 보여 줌. 보호자가 G6에서 "하루 동안 대화가 없으면 알려 주기"를 켰을 때만 다음 날 아침 푸시 (명세 6 대화 기록으로 판단, 11/25 B 안건)
2. **요약 받는 시각을 누가 정하나**: 명세 7은 어르신의 `report_send_time` 하나, 이슈 #52는 "보호자별 받을 시간". B 추천: A는 어르신의 `report_send_time` 전에 요약을 보내고, B가 보호자마다 자기 시각(같거나 더 늦은 시각)까지 `queued`로 두었다가 보냄. 그러면 명세는 안 바뀌고 G6에 "요약 받는 시각"을 둘 수 있음
3. **밀려난 알림 표시**: #68 11/28 안건(새 알림에 밀려난 알림)이 정해지면, G4에서 같은 대화의 알림을 묶어 보여 줄지
4. **`self_harm` 근거 발화**: 기본 숨김 + 한 번 더 눌러 보기 (B 추천) / 아예 안 보여 줌
5. **어르신 번호**: G5 전화 버튼용 번호를 보호자에게 보여 줄지(화면에 번호 표시) / 버튼만 둘지. B 추천: 버튼만 (번호는 보호자 폰 연락처에 이미 있음)
