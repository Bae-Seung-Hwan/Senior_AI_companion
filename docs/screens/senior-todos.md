# 할 일·약 화면 구성안 (#46)

어르신이 **오늘 할 일과 약**을 크게 보고, **버튼 하나나 말 한마디로** 끝냈다고 적는 화면입니다.
첫 시연 목표 "말로 할 일 등록 → 보호자가 요약 받기"의 가운데 단계입니다. 말로 등록한 할 일이 여기에 바로 보이고, 끝낸 할 일이 보호자 하루 요약의 "끝낸 할 일 N개"가 됩니다.

> 기술 스택(#1)과 상관없이 정할 수 있는 **화면 단위의 구성**입니다. 색·글꼴·컴포넌트는 앱 프레임워크가 정해진 뒤 정합니다 (공통 UI #5).
> 그림은 내용과 순서를 보여 주는 틀이고, 실제 배치는 시안에서 바꿀 수 있습니다.
> 보호자 화면은 `docs/screens/guardian.md` (#51, PR #76 리뷰 중)에 있습니다.

## 지키는 원칙

| 원칙 | 화면에서 |
| --- | --- |
| **음성 우선** (기획서 "모두 말로 입력하고 말로 들을 수 있어야") | 모든 화면에 **🔊 읽어 주기**가 있습니다. 할 일 추가는 **말로 추가하기**가 먼저, 손으로 추가하기는 그 아래에 둡니다 |
| 큰 글씨·큰 버튼, 한 화면 한 가지 일 (README 접근성) | 아래 "접근성 기준" 표 |
| **AI와 같은 말** (#72) | 날짜·시각·반복을 읽는 법과 문구를 A의 음성 문구(`server/companion/todos/speech.py`)와 똑같이 씁니다. 같은 할 일을 화면과 음성이 다르게 부르지 않습니다 |
| 의료 표현 금지 | "복용", "투약", "처방", "용량"을 쓰지 않습니다. 약 이름은 어르신이 말한 그대로(`title`). 약을 안 드셨다고 경고하거나 빨간색으로 표시하지 않습니다 |
| **감시 느낌 피하기** | 보호자는 이 화면을 볼 수 없습니다. 안 한 일·안 먹은 약을 보호자에게 바로 알리지 않습니다 (아래 "보호자가 볼 수 있는 것") |
| 실수해도 괜찮게 | 지우기는 한 번 더 묻습니다. "먹었어요"는 되돌릴 수 있습니다. 밀어서 지우기(스와이프) 같은 숨은 동작은 쓰지 않습니다 |

## T1. 오늘 할 일

앱 홈에서 가장 먼저 닿는 곳에 둡니다. **오늘 것만** 보여 줍니다.

```
┌─────────────────────────────────────┐
│ 오늘 할 일                           │
│ 11월 28일 토요일                      │
│ ┌───────────────────────────────┐   │
│ │        🔊 읽어 주기             │   │
│ └───────────────────────────────┘   │
├─────────────────────────────────────┤
│ 오전 8시 (아침)             매일     │  ← 반복 표시 (아래 규칙)
│ 혈압약                               │
│ ✔ 먹었어요 · 오전 8시 5분             │  ← 끝낸 것: 버튼 대신 표시, 자리는 그대로
├─────────────────────────────────────┤
│ 오후 3시 반                          │
│ 치과 예약                            │
│ ┌───────────────────────────────┐   │
│ │         다녀왔어요              │   │
│ └───────────────────────────────┘   │
├─────────────────────────────────────┤
│ 오후 9시 (주무시기 전)       매일     │
│ 혈압약                               │
│ ┌───────────────────────────────┐   │
│ │          먹었어요               │   │
│ └───────────────────────────────┘   │
├─────────────────────────────────────┤
│ 시간 안 정한 일                       │  ← 시각 미정 할 일 (아래 규칙)
│ 관리비 내기                           │
│ 알림 없음 · 시간 정하기 >             │
│ ┌───────────────────────────────┐   │
│ │           했어요                │   │
│ └───────────────────────────────┘   │
├─────────────────────────────────────┤
│ ┌───────────────────────────────┐   │
│ │       🎤 말로 추가하기          │   │
│ └───────────────────────────────┘   │
│ 손으로 추가하기 >     내일 할 일 보기 > │
└─────────────────────────────────────┘
```

### 보여 주는 것

| 칸 | 내용 | 데이터 |
| --- | --- | --- |
| 날짜 | "오늘 할 일" + 오늘 날짜·요일 | 사용자 시간대(명세 7 `timezone`) 기준 오늘 |
| 시각 | "오전 8시", "오후 3시 반" (아래 "시각 읽는 법") | `time`, 없으면 `time_hint`를 그 사용자의 기본 시각으로 바꾼 값 |
| 때 이름 | `time_hint`로 등록한 것은 시각 옆에 "(아침)", "(주무시기 전)" | `time_hint` |
| 제목 | 어르신이 말한 그대로 | `title` |
| 반복 | "매일" / "매주 월·목요일" | `repeat_freq`, `repeat_weekdays` |
| 끝냄 버튼 | 종류마다 다른 말 (아래 표) | 누르면 `todo_completions`에 한 줄 (`source: "tap"`) |

| 종류 (`kind`) | 버튼 | 누른 뒤 표시 | 누른 뒤 소리 |
| --- | --- | --- | --- |
| 약 (`medication`) | 먹었어요 | ✔ 먹었어요 · 오전 8시 5분 | "혈압약, 드신 걸로 적어 둘게요." |
| 일정 (`appointment`) | 다녀왔어요 | ✔ 다녀왔어요 | "치과 예약, 다녀오신 걸로 적어 둘게요." |
| 할 일 (`task`) | 했어요 | ✔ 했어요 | "관리비 내기, 하신 걸로 적어 둘게요." |

### 규칙

- **순서**: 시각 순서. 시간 안 정한 일은 맨 아래 "시간 안 정한 일" 묶음
- **끝낸 할 일은 자리를 옮기지 않습니다.** 버튼이 "✔ 먹었어요"로 바뀔 뿐 목록이 움직이지 않게 합니다 (누르자마자 줄이 사라지면 "어디 갔지?" 하게 됨). 줄을 긋거나 흐리게 하지도 않습니다
- **시각이 지났는데 안 끝낸 것**: 아무 표시도 더하지 않습니다. "놓침", "늦음", 빨간색 없이 버튼만 그대로 둡니다
- **시각 미정 할 일** (명세 1: `time`·`time_hint`가 둘 다 null): "시간 안 정한 일" 묶음에 두고 "알림 없음"을 함께 적습니다. A가 등록 때 "시간을 몰라서 알림은 따로 드리지 않을게요"라고 한 것과 같은 말입니다. **시간 정하기 >**는 T3의 "몇 시" 단계로 바로 갑니다
- **말로 등록한 것이 바로 보이게**: T1이 화면에 나올 때마다 B에서 다시 받아 옵니다. T5에서 등록하고 돌아오면 새 할 일이 이미 있어야 합니다
- **반복 할 일은 등록한 날부터** 보입니다 (명세 1: `date`가 null이면 B가 받은 날부터). 오후에 "매일 아침 혈압약"을 등록하면 오늘 아침 회차도 목록에 보이지만 알림은 울리지 않습니다 (이미 지난 시각)
- **할 일이 하나도 없는 날**: "오늘은 정해 둔 일이 없어요" 한 줄과 말로 추가하기 버튼만
- **읽어 주기**: "오늘 할 일은 네 가지예요. 오전 8시 혈압약, 드셨어요. 오후 3시 반 치과 예약. 주무시기 전 혈압약. 시간 안 정한 일, 관리비 내기." 말하기 속도는 명세 7 `tts_speed`
- **내일 할 일 보기**: 같은 모양으로 내일 하루만. 내일 화면에는 끝냄 버튼이 없습니다 (미리 끝낸 것으로 적지 않게)
- **어제 못 한 일**은 오늘로 넘기지 않습니다 (MVP). 넘길지는 "정할 것" 7번

### 보여 주는 것

| 칸 | 언제 | 데이터 |
| --- | --- | --- |
| 제목, 날짜(또는 반복), 시각 | 항상 | `title`, `date`, `time`/`time_hint`, `repeat_*` |
| 알림 | 항상. 시각 미정이면 "시간을 정하지 않아서 알림이 없어요" + 시간 정하기 | `reminders`의 다음 예약 |
| 오늘 끝냄 + 되돌리기 | 오늘 회차를 끝냈을 때 | `todo_completions` (오늘 회차) |
| 이번 주 | 반복 할 일만 | 이번 주 회차별 `todo_completions` |
| **이렇게 말씀하셨어요** | 말로 등록한 것만 (`source_type: "voice"`) | `original_text`, 등록 날짜 (#46 근거 발화) |

- **근거 발화는 어르신 본인에게만** 보입니다. 보호자 앱, 보호자 요약, 서버 로그 어디에도 나가지 않습니다 (명세 공통 "민감정보")
- 손으로 추가한 것(`manual`)은 "이렇게 말씀하셨어요" 칸이 없습니다
- **이번 주 기록**은 드신 날만 ✔를 두고 나머지는 점(·)입니다. ✗나 빨간색을 쓰지 않습니다. "내가 오늘 먹었나?"를 확인하는 용도입니다
- **되돌리기**는 오늘 회차만 됩니다. 누르면 `todo_completions` 그 줄을 지우고 T1 버튼이 다시 "먹었어요"로 돌아옵니다

## T3. 고치기·손으로 추가

**한 화면에 질문 하나**씩 묻습니다. 고치기는 바꿀 단계를 고르면 그 단계만, 손으로 추가하기는 처음부터 차례로 갑니다.

```
① 무엇을          ② 언제              ③ 몇 시             ④ 반복              ⑤ 확인
┌────────────┐  ┌────────────┐   ┌────────────┐   ┌────────────┐   ┌──────────────┐
│ 무엇을      │  │ 언제 하세요? │   │ 몇 시에     │   │ 되풀이      │   │ 이렇게        │
│ 하세요?     │  │             │   │ 알려 드릴까요?│  │ 하세요?     │   │ 등록할까요?    │
│             │  │ [  오늘   ]  │   │ [  아침   ]  │   │ [ 한 번만 ] │   │               │
│ [🎤 말하기]  │  │ [  내일   ]  │   │ [  점심   ]  │   │ [  매일   ] │   │ 내일 오후 3시 반│
│ ________    │  │ [  모레   ]  │   │ [  저녁   ]  │   │ [ 매주 …  ] │   │ 치과 예약      │
│             │  │ [다른 날 고르기]│ │ [주무시기 전]│   │             │   │               │
│ 약 / 일정 / │  │             │   │ [시각 고르기]│   │             │   │ [  네  ]       │
│ 할 일       │  │             │   │ [ 정하지 않음]│  │             │   │ [ 아니요 ]     │
└────────────┘  └────────────┘   └────────────┘   └────────────┘   └──────────────┘
```

- **① 무엇을**: 제목 칸 + 종류 세 개(약 / 일정 / 할 일) 큰 버튼. 자판 대신 **🎤 말하기**로 받아쓰기를 먼저 둡니다 (휴대폰 받아쓰기 또는 A의 STT, #1에서 정함)
- **② 언제**: 오늘 / 내일 / 모레 큰 버튼, 그 밖의 날은 달력. 반복을 고르면(④) 이 단계는 "언제부터"가 됩니다
- **③ 몇 시**: 아침 / 점심 / 저녁 / 주무시기 전은 `time_hint`로 저장합니다 (A가 "아침에"를 들었을 때와 같음). **시각 고르기**는 오전·오후와 시·분을 큰 버튼으로. 바퀴처럼 돌리는 선택기는 쓰지 않습니다. **정하지 않음**을 고르면 시각 미정(알림 없음)
- **④ 반복**: 한 번만 / 매일 / 매주(요일 7개 큰 버튼, 여러 개 고를 수 있음)
- **⑤ 확인**: A의 확인 질문과 같은 문장으로 크게 보여 주고 소리로도 읽습니다. A: "내일 오후 3시 반 치과 예약, 등록해 드릴까요?" → 화면: "이렇게 등록할까요? 내일 오후 3시 반 치과 예약"
- **다 된 뒤**: "등록해 두었어요. 오후 3시 반에 알려 드릴게요." (A의 `registered` 문구와 같음) → T1
- 고친 뒤에는 **알림을 다시 예약**합니다 (#47 "수정·삭제 시 알림 갱신"). 반복 할 일을 고치면 오늘 이후 회차에만 적용되고, 지난 완료 기록은 그대로 둡니다
- 이미 같은 할 일이 있으면(`DUPLICATE_TODO`와 같은 기준) "치과 예약은 이미 등록돼 있어요" + **그 할 일 보기 >** (A의 `already_registered` 문구와 같음)
- 지난 날짜·시각이면 "이미 지난 날짜나 시각이에요. 다시 골라 주세요" (A의 `invalid_date`와 같은 뜻)
- 고치기는 **B 앱 API**로 합니다 (아래 "B 서버에 필요한 것"). 명세 1(A ↔ B)에는 수정 API가 없어서, **말로 고치는 것**은 아직 안 됩니다 → "정할 것" 1번

## T4. 지우기 확인

```
┌─────────────────────────────────────┐
│                                     │
│ 치과 예약을 지울까요?                  │
│ 내일 오후 3시 반                      │
│                                     │
│ ┌───────────────────────────────┐   │
│ │          네, 지울게요           │   │
│ └───────────────────────────────┘   │
│ ┌───────────────────────────────┐   │
│ │         아니요, 둘게요          │   │
│ └───────────────────────────────┘   │
└─────────────────────────────────────┘
```

- 지우면 "치과 예약, 지웠어요." 소리와 함께 T1로 돌아갑니다. 아직 안 울린 알림은 취소합니다 (`reminders.status = 'canceled'`)
- 실제로는 `todos.deleted_at`만 채웁니다 (지운 할 일은 목록·중복 확인에서 빠짐, DB `todos_no_dup`). 지난 완료 기록은 남습니다
- **반복 할 일**은 "앞으로 다 지울까요? (혈압약, 매일 아침)"으로 묻습니다. "오늘만 건너뛰기"는 MVP에 넣지 않습니다
- 버튼 문구는 "확인/취소" 대신 무엇이 일어나는지 그대로 씁니다 ("네, 지울게요" / "아니요, 둘게요")

## T5. 말로 등록 확인 카드 (A 대화 화면 안)

어르신이 대화 중에 할 일을 말하면 A가 소리로 확인 질문을 하고(#72), **같은 내용을 대화 화면에 카드로 크게** 띄웁니다. 귀가 어두운 분도 눈으로 확인하고 버튼으로 대답할 수 있게 합니다.

```
┌─────────────────────────────────────┐
│ (A 대화 화면)                         │
│                                     │
│ 나: 내일 오후 세 시 반에 치과 예약 있어요 │
│ AI: 내일 오후 3시 반 치과 예약,          │
│     등록해 드릴까요?                   │
│ ┌─────────────────────────────────┐ │
│ │ 등록해 드릴까요?                   │ │
│ │                                 │ │
│ │ 내일 (11월 29일 일요일)             │ │  ← 크게
│ │ 오후 3시 반                        │ │
│ │ 치과 예약                          │ │
│ │                                 │ │
│ │ ┌────────────┐ ┌────────────┐   │ │
│ │ │     네      │ │   아니요    │   │ │
│ │ └────────────┘ └────────────┘   │ │
│ └─────────────────────────────────┘ │
│              🎤                      │
└─────────────────────────────────────┘
```

### 카드가 바뀌는 순서 (A 흐름 `flow.py`의 단계와 같음)

| A 단계 | A가 하는 말 (`speech.py`) | 카드 |
| --- | --- | --- |
| 시각을 물음 (`ask_time`) | "관리비 내기는 몇 시로 알려 드릴까요?" | "몇 시로 알려 드릴까요?" + 제목 + 버튼 **아침 / 점심 / 저녁 / 주무시기 전 / 몰라요** |
| 확인 (`confirm`) | "내일 오후 3시 반 치과 예약, 등록해 드릴까요?" | 위 그림. 날짜·시각·반복·제목을 줄마다 크게 + **네 / 아니요** |
| 다시 물음 (`ask_again`) | "…, 등록해 드릴까요? 네, 아니요로 말씀해 주세요." | 카드 그대로 (다시 읽어 줌) |
| 시각을 바로잡음 | "아니, 아침 여섯 시" → 고친 내용으로 다시 확인 | 고친 시각으로 카드를 다시 그림 |
| 등록됨 | "…, 등록해 두었어요. 오전 8시에 알려 드릴게요." | ✔ 등록해 두었어요 + 알림 시각 + **오늘 할 일 보기 >** (내일 이후면 "할 일 보기 >") |
| 시각 미정으로 등록됨 | "…, 등록해 두었어요. 시간을 몰라서 알림은 따로 드리지 않을게요." | ✔ 등록해 두었어요 + "알림 없음" |
| 거절 | "알겠어요, 등록하지 않을게요." | 카드를 닫음 |
| 이미 있음 (`409 DUPLICATE_TODO`) | "치과 예약은 이미 등록돼 있어요." | "이미 등록돼 있어요" + **보기 >** (`existing_todo_id`로 T2) |
| 지난 날짜 (`INVALID_DATE`) | "이미 지난 날짜나 시각이라 등록하지 못했어요. …" | 같은 문장, 카드를 닫음 |
| B 장애 | "지금은 등록이 잘 안 되네요. 조금 있다가 다시 말씀해 주세요." | 같은 문장, 카드를 닫음 |
| 두 번 못 알아들음 | (일반 대화로 넘어감) | 카드를 조용히 닫음 |

### 규칙

- **카드의 글은 A가 소리로 한 말과 같은 내용**입니다. 날짜는 "내일"처럼 말한 그대로 쓰고, 괄호에 실제 날짜·요일을 더합니다 (화면은 다시 볼 수 있어서 날짜를 같이 둠)
- **버튼은 말로 대답한 것과 똑같이** 처리합니다. "네"를 누르면 A 흐름에 "네"라고 말한 것으로 넘깁니다. 버튼을 눌렀다고 다른 길로 등록하지 않습니다 (명세 1 "동의한 뒤에만 호출"은 A가 지킴)
- 시각을 묻는 카드의 "몰라요"는 A의 `UNKNOWN_TIME`, 아침·점심·저녁·주무시기 전은 `time_hint`와 같습니다. 정확한 시각은 말로 대답합니다 (카드에 시계를 넣지 않음)
- 한 번에 여러 개를 말하면 A처럼 **하나씩** 카드를 띄웁니다. 카드 위에 "하나 더 있어요"만 작게 둡니다 (1/3 같은 숫자는 안 씀)
- 카드는 저절로 사라지지 않습니다. 대답할 때까지 그대로 둡니다
- 카드에 근거 발화를 따로 넣지 않습니다. 바로 위 대화 줄에 이미 보입니다

## T6. 알림 화면

정한 시각이 되면 푸시와 소리로 알리고(#47), 누르면 이 화면이 열립니다. 앱이 켜져 있으면 바로 이 화면으로 바뀌고 **소리로 읽어 줍니다**.

```
┌─────────────────────────────────────┐
│ 오전 8시                             │
│                                     │
│ 혈압약 드실                           │  ← 가장 크게
│ 시간이에요                            │
│                                     │
│ 매일 아침                             │
│                                     │
│ ┌───────────────────────────────┐   │
│ │          ✔ 먹었어요             │   │  ← 가장 큰 버튼
│ └───────────────────────────────┘   │
│ ┌───────────────────────────────┐   │
│ │    10분 뒤에 다시 알려 줘요       │   │
│ └───────────────────────────────┘   │
│ ┌───────────────────────────────┐   │
│ │         🔊 다시 듣기             │   │
│ └───────────────────────────────┘   │
└─────────────────────────────────────┘
```

| 종류 | 큰 글씨 | 첫 번째 버튼 | 두 번째 버튼 |
| --- | --- | --- | --- |
| 약 | "혈압약 드실 시간이에요" | ✔ 먹었어요 → `todo_completions` (`source: "reminder_button"`) | 10분 뒤에 다시 알려 줘요 |
| 일정 | "오후 3시 반에 치과 예약이 있어요" | 알겠어요 (끝냄으로 적지 않음. 다녀온 뒤 T1에서 "다녀왔어요") | — |
| 할 일 | "관리비 내기, 잊지 마세요" | ✔ 했어요 → `todo_completions` | 10분 뒤에 다시 알려 줘요 |

### 규칙

- **푸시에서 바로 끝내기** (#47): 알림 자체에 "먹었어요" 버튼을 둡니다 (Android·iOS 알림 버튼). 앱을 열지 않고 눌러도 같은 기록이 남습니다 (`source: "reminder_button"`)
- **소리로 읽기**: TTS는 A와 같은 것을 씁니다 (#47). 말하기 속도는 `tts_speed`. 앱이 닫혀 있을 때 푸시 소리 대신 문장을 읽어 줄 수 있는지는 기술 스택에 따라 다릅니다 (#47 조사)
- **말로 대답하기**: "먹었어", "다시 알려 줘"로 대답하는 것이 목표지만, A ↔ B에 완료 API가 없어서 지금은 버튼만 됩니다 → "정할 것" 2번
- **다시 알림**: 아무것도 누르지 않으면 10분 뒤 한 번 더 울리고 그 뒤로는 울리지 않습니다 (B 추천, "정할 것" 6번). **보호자에게는 알리지 않습니다**
- 그 회차를 T1에서 **미리 끝냈으면** 알림을 취소합니다 (아직 안 보낸 `reminders`만)
- 화면은 저절로 닫히지 않습니다. 버튼을 누르거나 뒤로 가기로 닫습니다
- 잠금 화면에서 화면 전체를 띄우는 것(알람 앱처럼)은 OS 제한이 있어서 MVP는 **푸시 + 소리**로 하고, 누르면 T6을 엽니다

## 반복 표시 (매일·매주)

| 저장된 값 | T1 (오늘) | T2 (상세) | 소리 (A와 같음) |
| --- | --- | --- | --- |
| `repeat_freq: daily`, `time_hint: morning` | "오전 8시 (아침)" + "매일" | "매일 아침 · 오전 8시" | "매일 아침 혈압약" |
| `repeat_freq: weekly`, `weekdays: [MON, THU]`, `time: 09:00` | 월·목요일에만 "오전 9시" + "매주 월·목요일" | "매주 월·목요일 · 오전 9시" | "매주 월·목요일 오전 9시 수영" |
| 반복 없음 | 그날에만 | "11월 29일 일요일 (내일)" | "내일 오후 3시 반 치과 예약" |

- T1에는 **오늘 회차만** 한 줄로 나옵니다. 매주 반복은 해당 요일이 아니면 오늘 목록에 없습니다
- 하루 두 번 드시는 약(아침·저녁)은 **할 일 두 개**입니다 (`time_hint`가 할 일마다 하나라서). T1에 두 줄로 나오고 각각 따로 "먹었어요"를 누릅니다
- 회차마다 완료 기록이 따로 남습니다 (`todo_completions.occurrence_date`)
- 반복이 언제 끝나는지(`repeat_until`)는 MVP 화면에서 정하지 않습니다. 그만 드시게 되면 T4로 지웁니다

## 시각 읽는 법 (A와 같게)

화면 글자와 소리가 같아야 해서 A의 `speech.py` 규칙을 그대로 씁니다. 숫자 시각("15:30")이나 24시 표기는 쓰지 않습니다.

| 값 | 화면·소리 |
| --- | --- |
| 00:00 | 밤 12시 |
| 01:00~05:59 | 새벽 N시 |
| 06:00~11:59 | 오전 N시 |
| 12:00~12:59 | 낮 12시 |
| 13:00~23:59 | 오후 N시 |
| :30 / :00 / 그 밖 | "반" / 시만 / "N분" |
| `time_hint` | 아침 / 점심 / 저녁 / 주무시기 전 |
| 날짜 | 오늘 / 내일 / 모레 / "11월 30일 월요일" (해가 바뀌면 연도 붙임) |
| 반복 | 매일 / 매주 월·목요일 |

A와 B가 같은 규칙을 따로 만들면 언젠가 어긋나므로, 앱 쪽 코드가 생기면 **표 하나(이 표)로 둘 다 테스트**하는 것을 제안합니다.

## 접근성 기준 (어르신 화면 공통)

공통 UI(#5)를 만들 때 이 값으로 시작하고, 사용자 테스트에서 고칩니다. 숫자는 초안입니다.

| 기준 | 어르신 화면 |
| --- | --- |
| **글씨 크기** | 기본 글씨를 휴대폰 기본보다 30% 크게 (DB `user_preferences.font_scale` 기본 1.30). 본문은 최소 20pt 정도, 제목·시각은 더 크게. 휴대폰 글씨 크기 설정을 더 키워도 글자가 잘리지 않고 줄이 바뀜 (가로로 밀어 보는 화면 없음) |
| **버튼 크기** | 높이 최소 64dp 정도, 화면 폭을 거의 채움. 버튼 사이 간격 16dp 이상. 버튼 안에 글자를 꼭 넣음 (아이콘만 있는 버튼 없음) |
| **한 화면 한 가지 일** | 화면마다 가장 중요한 버튼 하나를 가장 크게. 입력은 T3처럼 한 화면에 질문 하나 |
| **음성으로도 다 할 수 있음** | 모든 화면에 🔊 읽어 주기. 추가는 말로가 먼저. 끝내기·고치기를 말로 하는 것은 A ↔ B API가 필요 ("정할 것" 1·2번) |
| 느린 말하기 | 읽어 주기·알림 소리는 `tts_speed` (보호자 원격 설정 #43으로도 바꿀 수 있음, 어르신 동의 후) |
| 누르기만 | 밀기(스와이프), 길게 누르기, 두 손가락 동작을 쓰지 않음. 시각 고르기도 바퀴 대신 버튼 |
| 시간 제한 없음 | 확인 카드·알림 화면이 저절로 닫히지 않음 |
| 색에만 기대지 않음 | 끝낸 것은 ✔와 글자("먹었어요")로. 대비는 WCAG AA(4.5:1) 이상, 가능하면 7:1 |
| 쉬운 말 | "삭제" → 지우기, "편집" → 고치기, "완료" → 했어요·먹었어요·다녀왔어요, "확인/취소" → "네, 지울게요 / 아니요, 둘게요" |
| 의료 표현 금지 | "복용·투약·처방·용량"을 쓰지 않음. 약을 안 드셨다는 경고 없음 |

## 보호자가 볼 수 있는 것 / 없는 것

**보호자 앱에는 할 일 목록 화면이 없습니다** (guardian.md G1~G6). 보호자는 하루 요약으로만, 그것도 **일정 공유를 켰을 때만** 알 수 있습니다. 공유 범위는 어르신만 바꿉니다 (명세 7).

| 어르신 화면의 것 | 보호자에게 |
| --- | --- |
| 할 일 목록, 제목, 시각 | 보이지 않음 |
| 끝낸 할 일 수 | 일정 공유를 켰을 때 하루 요약에 "끝낸 할 일 N개" (G3, `stats.completed_todos`). 0이면 줄이 없음 |
| 다녀온 일정 | 일정 공유를 켰을 때 A가 쓴 요약 문장(`sections.schedule`) 안에서만 |
| 약을 드셨는지, 약 이름 | 어느 공유 범위로 볼지 아직 안 정함 → "정할 것" 3번 (B 추천: 건강 공유) |
| **안 한 일·안 먹은 약** | 바로 알리지 않음. B는 "약을 안 드셨어요" 같은 보호자 푸시를 만들지 않음 |
| 근거 발화 ("이렇게 말씀하셨어요") | 절대 보이지 않음 |
| 다시 알림을 눌렀는지, 알림을 늦게 껐는지 | 보이지 않음 |
| 고치거나 지운 기록 | 보이지 않음 |

### 보호자 원격 설정 (#43)과의 관계

- 보호자가 원격으로 도울 수 있는 것은 **설정 값**입니다: 아침·점심·저녁·주무시기 전 기본 시각(`time_hints`), 글씨 크기(`font_scale`), 말하기 속도(`tts_speed`). **어르신이 동의해야** 적용됩니다
- 어르신 앱에는 이렇게 묻습니다: "따님이 아침 시각을 오전 8시에서 오전 7시 반으로 바꾸자고 하셨어요. 아침에 드시는 약 알림도 오전 7시 반으로 바뀌어요. 바꿀까요?" **네 / 아니요**
- 기본 시각이 바뀌면 그 `time_hint`로 등록한 할 일의 **앞으로의 알림을 다시 예약**합니다. 누가 바꿨는지는 `user_preferences.updated_by`에 남습니다
- 보호자는 어르신의 할 일을 **추가·고치기·끝내기 할 수 없습니다** (MVP). 보호자가 할 일을 보내는 기능(`source_type: "guardian_assist"`)은 "정할 것" 8번
- 공유 범위는 원격 설정으로도 못 바꿉니다 (DB에서도 막음)

## B 서버에 필요한 것 (어르신 앱 ↔ B, A와는 무관)

명세(A ↔ B)가 아니라 B 안의 API라서 `docs/api-contracts.md`에는 넣지 않습니다. 기술 스택이 정해지면 같이 만듭니다 (#44, #47).

| API (가칭) | 화면 | 데이터 |
| --- | --- | --- |
| `GET /senior/todos?date=YYYY-MM-DD` | T1 | 그날의 **회차 목록**: 반복 할 일을 그날 회차로 펼치고, `time_hint`를 그 사용자의 기본 시각으로 바꾼 값, 끝냈는지(`todo_completions`), 시각 미정 여부 |
| `GET /senior/todos/{id}` | T2 | 상세 + `original_text`(본인에게만) + 다음 알림 + 이번 주 완료 기록 |
| `POST /senior/todos` | T3 | 손으로 추가 (`source_type: "manual"`). 검사는 명세 1과 같음 (`MISSING_TITLE`, `INVALID_DATE`, `409 DUPLICATE_TODO` + `existing_todo_id`) |
| `PATCH /senior/todos/{id}` | T3 | 고치기. 알림 다시 예약. 반복이면 오늘 이후 회차만 |
| `DELETE /senior/todos/{id}` | T4 | `deleted_at` 채움, 안 보낸 알림 취소 |
| `POST /senior/todos/{id}/completions` | T1, T6 | `{ occurrence_date, source: "tap" \| "reminder_button" }`. 같은 회차를 두 번 눌러도 한 줄 (DB UNIQUE) |
| `DELETE /senior/todos/{id}/completions/{occurrence_date}` | T2 | 되돌리기 (오늘 회차만) |
| `POST /senior/reminders/{id}/snooze` | T6 | 10분 뒤 다시 알림 (`reminders`에 새 줄) |

- DB는 지금 스키마(#65)로 거의 됩니다: `todos`, `todo_completions`(`source`에 `tap`·`reminder_button` 있음), `reminders`, `user_preferences`(`time_hints` 4개, `font_scale`, `tts_speed`, `quiet_start/end`)
- 다시 알림이 몇 번째인지 셀 칸이 `reminders`에 없습니다. "10분 뒤 한 번만"이면 같은 회차의 `reminders` 줄 수로 셀 수 있어서 스키마는 안 바꿔도 됩니다
- 완료 되돌리기는 `todo_completions` 줄을 지웁니다 (따로 취소 기록을 남기지 않음). 하루 요약을 이미 보낸 뒤 되돌리면 요약은 그대로입니다
- 화면 시안은 할 일 mock(`tools/mocks/todo_mock.py`)의 `GET /todos?user_id=…`로 말로 등록한 할 일을 바로 그려 볼 수 있습니다. 회차 펼치기·완료는 mock에 없어서, 화면 작업을 시작할 때 mock에 더합니다

## 정할 것 (#68)

1. **말로 고치기·시각 붙이기** (A ↔ B): 명세 1에 수정 API가 없어서 "치과 4시로 바꿔 줘", 시각 미정 할 일에 "그거 3시야"를 A가 처리할 수 없음 (#72 안건과 같음). 화면 고치기(T3)는 B 앱 API로 됨. B 추천: 명세 1에 `PATCH /todos/{todo_id}` (날짜·시각만) 추가. 지우기는 MVP에서 화면으로만
2. **말로 끝내기·오늘 할 일 읽어 주기** (A ↔ B): 기획서 "'약 먹었어' 한 마디로 기록"과 AI에게 "오늘 뭐 있지?" 묻기에 필요한 완료·조회 API가 명세에 없음. T6에서 말로 대답하는 것도 이것이 필요함. B 추천: 명세 1에 `POST /todos/{todo_id}/completions`(`source: "voice"`)와 `GET /todos?user_id=…&date=…` 추가. 어느 할 일인지 고르는 것은 A가 조회 결과로 함
3. **약 기록의 공유 범위**: 보호자 요약에서 약 이름과 드셨는지를 일정 공유로 볼지 건강 공유로 볼지. 약 이름으로 병을 짐작할 수 있어서 B 추천: **약은 건강 공유**, "끝낸 할 일 N개"(숫자만)는 일정 공유. 정해지면 guardian.md G3 예시 문장("혈압약도 잘 챙겨 드셨어요"가 일정 칸에 있음)과 A의 요약 작성도 맞춰야 함
4. **방해 금지 시간과 할 일 알림**: 명세 7은 어르신 `quiet_hours`(기본 22:00~07:00)가 할 일 알림을 미룬다고 함. 그러면 어르신이 정한 "밤 11시 약"이 아침으로 밀림. B 추천: **어르신이 정한 시각의 알림은 미루지 않고**, 다시 알림·미리 알림만 미룸
5. **일정 미리 알림**: 지금 `remind_before_minutes` 기본은 0이라 "오후 3시 반 치과" 알림이 3시 반에 울림. B 추천: 일정(`appointment`)은 1시간 전 + 그 시각 두 번, 약·할 일은 그 시각 한 번. 말로 등록할 때는 묻지 않음 (확인 질문이 길어짐)
6. **다시 알림 횟수**: B 추천: 대답이 없으면 10분 뒤 한 번 더, 그 뒤로는 안 울림. 보호자에게는 알리지 않음
7. **어제 못 한 일**: 한 번짜리 할 일을 안 끝내고 날이 바뀌면 오늘 목록에 다시 보일지. B 추천: 할 일(`task`)만 "지난 할 일"로 3일까지 보이고, 약·일정은 넘기지 않음. MVP는 넘기지 않음
8. **보호자가 할 일 보내기** (`source_type: "guardian_assist"`, #43): 자녀가 병원 예약 등을 보내면 어르신이 "네"를 눌러야 등록되는 기능을 MVP에 넣을지. B 추천: MVP 이후. MVP 원격 설정은 기본 시각·글씨 크기·말하기 속도만
