# A 서버 (말벗 AI)

> 기술 스택(#1)이 정해지기 전이라 **Python 3.10+** 로 기능 로직만 먼저 만듭니다. HTTP 서버·앱 연결은 스택이 정해지면 붙입니다.
> B 연결은 [연결 지점 명세](../docs/api-contracts.md)를 따르고, B 실제 서버 전에는 B mock(`tools/mocks/`)에 붙입니다.

## 말로 할 일 등록 (#22, 명세 1)

```
어르신: 내일 오후 세 시 반에 치과 예약 있어요
AI:     내일 오후 3시 반 치과 예약, 등록해 드릴까요?
어르신: 네
AI:     내일 오후 3시 반 치과 예약, 등록해 두었어요.      ← 이때만 B POST /todos 호출
```

| 파일 | 하는 일 |
| --- | --- |

### 지키는 규칙

- **동의한 뒤에만 B를 호출합니다.** "네"가 아니면 등록하지 않습니다. 두 번 알아듣지 못하면 접고 일반 대화로 넘깁니다
- **시각을 추측하지 않습니다.** "아침에"는 `time_hint: "morning"`으로 보내고 B가 사용자별 기본 시각으로 바꿉니다. 등록 뒤에는 B가 정한 실제 시각을 알려 드립니다 ("오전 8시에 알려 드릴게요")
- 오전·오후를 말하지 않은 1~6시는 오후로 보고, 확인 질문에서 "오후 3시"로 다시 읽어 드립니다. 확인 질문에 **"아니, 아침 여섯 시"처럼 시각을 바로잡으면** 고친 시각으로 다시 확인합니다 (같은 말에 다른 할 일이 있으면 바로잡기가 아니라 새 할 일로 봄)
- **"네?", "예? 뭐라고요?"처럼 되물으면 동의로 보지 않고** 내용을 다시 읽어 드립니다. STT가 물음표를 빼먹을 수 있어서 "뭐라고", "못 들" 같은 말도 되묻기로 봅니다. "네네", "예예"는 동의입니다
- 시각도 대략적인 때도 없으면 "몇 시로 알려 드릴까요?"를 **한 번만** 묻고, 모르면 시각 없이 등록합니다 (B는 알림 없이 저장, "알림은 따로 드리지 않을게요"라고 안내). 나중에 시각을 붙이는 방법은 명세 1에 수정 API가 없어서 회의(#68) 안건입니다
- 같은 대화에서 **끝난 할 일**(등록함, 이미 있음, 거절함)은 다시 제안하지 않습니다. 제목·날짜·시각·반복이 모두 같아야 같은 할 일입니다 ("다음 주 화요일에도 치과"는 새로 제안)
- 등록에 실패하면("다시 말씀해 주세요") 끝난 것으로 치지 않아서, 다시 말하면 다시 제안합니다
- 한 번에 여러 개를 말하면 하나씩 확인합니다. 확인 질문에 새 할 일을 말해도 뒤에 줄 세워 묻습니다
- 헷갈리는 대답은 거절 쪽으로 봅니다 ("그래도 안 할래요" → 거절). 단 "잊지 말고 꼭 알려 줘"는 동의입니다
- 할 일 추출 Claude 호출도 대화 턴 안이라 짧게 기다립니다 (8초 × 재시도 1번, `companion/llm.py`). 늦으면 할 일 제안만 건너뜁니다
- **음성 대화 중 B 재시도는 짧게** 합니다: 3초 시간 초과 × 2번 + 1초 간격(최대 약 7초). 공통 규칙(1·3·10초, 3번 재시도)대로 하면 "네" 뒤에 30초 넘게 말이 없을 수 있어서입니다. 실패하면 "조금 있다가 다시 말씀해 주세요"로 안내하고, 뒤에서 다시 보내는 것은 음성 연결 때 추가합니다
- 대화 원문(`original_text`)은 로그에 남기지 않습니다

### 지키는 규칙

- **brief는 LLM이 쓰지 않고 대화 횟수로 만듭니다** ("오늘 AI와 세 번 이야기를 나누셨어요."). brief는 공유 범위와 상관없이 모든 보호자에게 가고 잠금 화면에 뜨는 푸시 본문에도 들어가서, 일정·건강·기분 내용이 샐 길을 아예 없앴습니다. 대화 횟수는 `stats`로 어차피 항상 가는 정보입니다
- **각 section에는 자기 항목 내용만** 넣습니다. 보호자는 동의한 항목만 받기 때문에, 예를 들어 기분만 공유했는데 mood에 "치과 가기 귀찮아하셨어요"가 있으면 일정이 새어 나갑니다
- 의료 표현을 쓰지 않습니다 ("치매", "건망증", "기억력", 병명, "진단", "증상", "가 보셔야" 같은 의료 조언 등)
- 위 규칙은 프롬프트로 지시하고, **보내기 전에 단어 목록으로 한 번 더 검사**합니다. 걸리면 이유를 알려 주고 한 번 다시 쓰게 하고, 그래도 걸리면(또는 다시 쓰기 호출이 실패하면) 해당 section은 뺍니다 (동의하지 않은 내용이 새는 것보다 빠지는 편이 낫다고 봄)
- 단어 목록은 완벽하지 않습니다. 놓치는 표현도 있고, 멀쩡한 문장이 걸려 section이 빠질 수도 있습니다. 짧은 말은 다른 낱말 안에 들어 있기 쉬워서("스마트폰"의 "마트", "대화가"의 "화가", "붓글씨"의 "붓") 좁혀 두었습니다
- section을 빼도 `mood_level`은 보냅니다. 기분 공유 동의 여부로 B가 따로 거르고, "며칠째 low" 판단에 쓰이기 때문입니다
- 대화 횟수(`stats.conversation_count`, brief, 프롬프트의 "대화 N번")는 모두 어르신이 한 마디라도 한 대화만 셉니다. 다른 날짜(한국 시간 기준)에 시작한 대화는 뺍니다
- 대화가 없는 날은 보내지 않습니다 (임시, 아래)
- 화면·로그에는 상태만 남기고, 요약 문장은 `--out` 폴더(`.gitignore`)에만 저장합니다
- **같은 날짜로 다시 돌려도 안전합니다.** 결과 파일이 그날의 기록입니다
  - B가 받았거나(`accepted`) 이미 보호자에게 보냈으면(`already_sent`) 아무것도 하지 않습니다. 보호자가 실제로 받은 내용의 기록이 지워지지 않습니다
  - `accepted`는 "B가 받음(202)"입니다. 보호자에게 실제로 갔는지는 응답의 `deliveries[].status`를 봅니다 (무료 등급은 `scheduled`라 다음 주에 받음)
  - `already_sent`를 받으면 이번에 보낸 본문은 보호자가 받은 것이 아니라서 기록에 `request`를 남기지 않습니다
  - B가 응답하지 않았으면(`unavailable`) 요약을 새로 쓰지 않고 **같은 `request_id`로 같은 본문을 다시 보냅니다** (B는 받았는데 응답만 끊긴 경우에도 중복이 생기지 않게). 사용자 없음(`user_not_found`)·거절(`rejected`)도 Claude를 다시 부르지 않고 같은 본문을 다시 보냅니다
  - 그 밖(쓰기 실패, 대화 없음)은 처음부터 다시 합니다
- 입력 파일 하나가 깨져도 다른 사용자는 계속 돌리고, 실패가 있으면 종료 코드 1로 끝납니다

- **대화가 없는 날**: 지금은 보내지 않습니다. "오늘은 대화가 없었어요"를 보호자에게 알리면 안부 확인이 되지만 감시 느낌을 줄 수 있습니다. `mood_level`이 필수라 보낸다면 값도 정해야 합니다

### 지키는 규칙

- **할 일 흐름보다 먼저** 봅니다. `SafetyConversation.handle()`이 `None`이면 위험한 말이 아니므로 할 일·일반 대화로 넘깁니다
- 사기 유형: 가족·지인 사칭, 검찰·경찰·금융기관 사칭, 고수익 투자, 대출 미끼, 로맨스 스캠, 당첨·환급 미끼, 앱 설치·인증번호 요구, 그 밖의 돈·개인정보 요구
- 단계: 이미 거절함(`refused`) / 받았음(`received`) / 따르려 함(`about_to_act`) / 이미 따름(`already_acted`)
  - **거절했으면 보호자에게 알리지 않고** "잘하셨어요"만 합니다 (감시 느낌 줄이기)
  - severity: 따르려 하거나 이미 따랐으면 `high`. 받기만 했으면 그날 바로 돈이 나가는 유형(가족 사칭, 기관 사칭, 앱·인증번호)은 `high`, 나머지는 `medium`
- **severity와 보호자에게 보일 설명(`reason`)은 코드가 정합니다.** 모델에게는 유형·단계만 받습니다 (모델이 지어낸 글이 보호자에게 가지 않게)
- LLM 판단 확신이 낮으면(`low`) 알리지 않습니다. LLM 호출이 실패하거나 늦으면(8초 × 2번) 규칙 안전망만으로 알립니다. 안전망은 LLM 없이 보호자에게 긴급 푸시를 보내므로 좁게 잡았습니다 ("딸이 택배 보냈대", "병원 검사 결과 보내 준대"는 걸리지 않음)
- 문지기는 넓게 잡되, 흔한 낱말 안에 든 짧은 말("기억"의 "억", "건강검사"의 "검사", "사진 보내"의 "보내", "경찰서", "택배")에는 걸리지 않게 했습니다. 일상 대화마다 LLM을 부르지 않기 위해서입니다
- 경고는 탓하지 않고 할 일 하나만 말합니다: "돈을 보내거나 번호를 알려 주기 전에 꼭 가족에게 먼저 확인해 주세요". 이미 보냈다면 112나 은행에 바로 전화하도록 안내합니다
- **보호자에게 알렸으면 숨기지 않고** "보호자분께도 알려 드렸어요"라고 말합니다. B가 응답하지 않았거나 보호자에게 못 갔으면 그렇게 말하지 않습니다
- 같은 대화에서 **같은 유형의 사기**로 경고를 되풀이하지 않습니다. 더 위급해졌을 때(`medium` → `high`)만 새로 알리고, 다른 유형의 사기는 따로 알립니다
- 어르신 선택: "확인해 볼게"(`guardian_check_requested`), "전화 걸어 줘"(`guardian_call_requested`), "괜찮아", "아니", "싫어"(`dismissed`). 섞이면 확인 쪽으로 봅니다. 그냥 "네"·"아니"는 짧은 대답일 때만 선택으로 봅니다 ("내일 치과 예약해 줘"의 "해 줘"는 동의가 아님)
- "네?"처럼 되물으면 한 번 다시 묻습니다. 대답이 아닌 말("내일 치과 예약해 줘")은 붙잡지 않고 할 일·일반 대화로 넘기며, 화면 버튼(#27)의 `respond()`나 대답 없음 `expire()`(`no_response`)를 기다립니다
- **대답을 기다리는 동안에도 감지는 계속합니다.** "알았어, 그래도 지금 은행 가서 보낼게", "벌써 인증번호 알려줬어"처럼 더 위급해지면 새로 알리고, 앞 알림에는 그 대답(없으면 `no_response`)을 보내서 B에 `pending`으로 남지 않게 합니다
- B가 응답하지 않아도 경고는 그대로 하고, 보내지 못한 4-1·4-2는 `flush()`에서 **같은 `request_id`로** 다시 보냅니다. 사용자 없음·형식 거절처럼 다시 보내도 같은 실패는 다시 보내지 않습니다 (원문이 B로 되풀이해 가지 않게)
- 발화 원문은 로그에 남기지 않습니다. 감지 기록(`events`)에도 원문은 없고 유형·단계·severity·선택만 남깁니다 (원문은 B에 `evidence.text`로만 감, 명세 4)
